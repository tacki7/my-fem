# 検証結果

すべて `npm run build` と同じソースから、Node 上で定常まで走らせた値。
基準はスラブ法（Siebel / von Kármán）: `p̄ = kf·(e^a − 1)/a`, `a = μL/h̄`, `L = √(RΔh)`。
変形抵抗はひずみ平均の平均変形抵抗 `σ̄f = σ_Y0 + K·ε₁ⁿ/(n+1)` を使い、`kf = (2/√3)σ̄f`。

共通条件: R = 100 mm, h₀ = 8 mm, σ_Y0 = 250 MPa, K = 500 MPa, n = 0.25, ω = 3 rad/s（R = 100 mm なので周速 18 mpm）,
板メッシュ 100×8, ロール 200×5, 解析窓は自動フィット。

> **この条件は現在の既定ではない。** 測定時の既定は R = 100 mm・Ludwik 式だったが、現在の
> 既定は冷間圧延 (薄板) プリセット（R = 190 mm, h₀ = 2 mm, μ = 0.06, 周速 68.4 mpm — 2026-09-12 からはライン出側板速度 100 mpm が既定, ミル剛性 M 5 MN/mm — 同日から 5.8 MN/mm が既定,
> LMN 式 `kf = L(ε̄+M)^N` の L = 1200 MPa, M = 0.010, N = 0.255）。旧 Ludwik との
> 対応は標準 (中板) プリセット（L = 954 MPa, M = 0.010, N = 0.259）で見ている。
> LMN は ε̄ = 0 と ε̄ ≈ 0.356 で旧曲線に一致させた再フィットで、中間では最大 −24%、
> 25% 圧下のひずみ平均 kf は 645 → 594 MPa（−8.0%）。下の数値をそのまま再現するには
> 上記の旧パラメータで走らせる必要がある。

> 板厚方向の列平均（入出側速度 → 前方すべり・後進率・質量収支）は台形則。以前は矩形則で、
> 表層節点 2 つを半セルぶん過大に重み付けしていた（ny に対して一次の誤差）。下表の `fs%` は
> その修正前に採った値で、修正後との差は 0.15 pt 以内。

## 読み方

- **Picard 1 と 3 が一致**（P = 9.53 kN/mm、Picard 変化率 0）。状態をフレーム間で持ち越すので
  毎フレーム 1 反復で十分収束する。既定値を 1 にしている根拠。
- **圧下率スイープ**: FEM/スラブ法比が 1.02 → 0.77 と圧下率とともに下がる。スラブ法は均一圧縮を
  仮定するので大圧下側で過大評価するのが既知の性質で、その傾向どおり。相当ひずみは理論値
  (2/√3)ln(h₀/h₁) とよく一致。
- **摩擦スイープ**: μ とともに荷重・最大面圧が増え、前方すべりが 0.63% → 5.86%、中立点が
  −0.72 mm → −5.39 mm と上流へ動く。いずれも教科書どおりの傾向。
  μ = 0.05 では噛み込み条件 μ ≥ tan α (= 0.142) を満たさず、中立点が消え圧延が成立しない。
- **ロール扁平**: 2 mm 板を 25% 圧下する冷間条件で、剛体ロールなら h₁ = 1.500 mm・P = 6.30 kN/mm。
  弾性連成を入れると胴面が 38 µm 扁平してギャップが開き、h₁ = 1.579 mm・P = 5.73 kN/mm になる。
  実際の圧下率が指令値より小さくなるという、冷間圧延で R' を使う理由そのもの。

## 入出側の弾性変形

剛塑性体には弾性ひずみが無いので、そのままだと入出側は完全剛体になる。粘度の上限を材料自身の
弾性応答 `G·t`（t = ビット通過時間）に、体積項を真の体積弾性率 `K·t` に置き換えると、
非塑性域が弾性的に振る舞うようになる。板厚変化の内訳は

```
h₀ →(弾性圧縮 Δh_e = h₀kf/E′)→ 降伏 →(塑性圧下 Δh_p)→ ギャップ →(弾性回復 Δh_r)→ h₁
```

  上げてもロールが扁平して逃げるので、圧下に回る分が減る。定圧延荷重制御で薄板を狙うほど
  圧下率が荷重に鈍感になるという、開ループの圧下達成率の傾向と表裏一体。

- **スプリングの内訳が逆転する**。剛体スタンドでは 101.8 µm すべてがロール扁平＋弾性回復。
  M = 5 MN/mm を入れるとハウジング伸びが 1123 µm と一桁以上大きくなり、実機どおり
  ミルスプリングの主役になる。扁平のほうは荷重が下がるぶん 101.8 → 78.8 µm に減る。
- **スクリュー固定なら圧下率が壊滅する**。M = 5 MN/mm では指令 25% が実測 9.97%（達成率 0.399）。
  M = 1 MN/mm では 1.4% しか圧下できない。実機がスクリュー位置ではなく板厚を制御する理由。
- **AGC はこれを完全に取り返す**。どの剛性でも圧下達成率は 1.000。取り返し方は「スクリューを
  伸び分だけ余計に締める」で、S は M = 3 MN/mm なら 5.896 → 2.708 mm まで下がる。
- **薄板ではスクリュー指令が負になる**。h₀ = 0.5 mm を 25% 圧下するのに、M = 3 MN/mm なら
  S = −0.444 mm（無負荷なら上下ロールが 0.44 mm 食い込む位置）。ハウジングが 792 µm 伸びて
  実ギャップが正になる。冷延薄板で負のギャップ設定が常識なのはこのため。
  M を上げると負の量が減り（−0.444 → −0.127 → +0.111 mm）、10 MN/mm では正に戻る。
- **収束はミルが柔らかいほど遅い**（67f → 540f、薄板では 821f → 3249f）。スタンドが伸びる
  ぶんスクリューを余計に動かす必要があり、しかもスクリューは内側のミルスプリング・ループが
  落ち着くのを待ってから動くため。

## 自由表面条件（接触弧の外）と大圧下での荷重

「圧下を増やすと荷重が減る」現象を調べたところ、原因は非圧縮の破綻ではなく
**接触弧の外の上面に運動学的条件が無く、材料が固定メッシュを突き抜けていた**ことだった。

局所的な体積ひずみは健全（`mean |div v| / ひずみ速度` は r=95% でも 5.4e-4）なのに、
入口から出口までの流量は r=93% で 0.486 まで落ちる。損失は**接触弧に入る前の平坦な助走区間**で
起きていた:

```
r=93%, 板厚一定の入側（h/2 = 4.000 mm）での累積流量比
  x=-81.8mm 1.000 → -73.2mm 0.907 → -62.2mm 0.822 → -52.4mm 0.744
          → -42.6mm 0.671 → -32.7mm 0.602 → -30.3mm 0.532（ここでビット入口）
  ビット内: 0.532 → 0.505   出側: 0.486
```

上面の v_y / v_x（本来 s′ = 0 なのでゼロであるべき）: r=25% で −2.6e-6、r=70% で +2.2e-3、
r=93% で **+4.5e-2**。

## 摩擦係数の逆算（μ逆算）

**測定条件** — 現在の既定（冷間圧延 (薄板) プリセット）: R = 190 mm, LMN 式

### 往復（μ → 荷重 → μ）

設定した μ から順方向で荷重を作り、その荷重だけを渡して μ を解き直す。

```
 case                            mu_in    P[tonf]   mu_out     dmu[%]     dP[%]
 h 2.0->1.5, σ 0/0              0.0600    1434.6  0.060000   -1.1e-13    0.0e+0
 h 2.0->1.5, σ 30/60            0.0600    1327.6  0.060000   -2.2e-14    0.0e+0
 h 1.5->1.15, ε0=0.332          0.0400    1599.3  0.040000   -8.9e-14   -1.5e-14

 h 20->14 (熱間, R=350)         0.2500    7732.9  0.250000   -4.4e-14   -2.6e-14
 h 0.8->0.6, ε0=1.2             0.0150     954.4  0.015000   -2.1e-13    0.0e+0
```

`dP` は求めた μ を**順方向のモデルに戻した**ときの荷重誤差で、倍精度の丸め（1e-14 % 台）。
広く振ったスイープ（板厚 4 水準 × 圧下率 3 × 張力 3 × ロール径 3 × 入側ひずみ 3 × μ 6
= 1521 往復）でも `|dμ|` 最大 1.4e-13、`|dP|` 最大 1.3e-14。

### 現在の運転点から離れた入力で解けること

過去にここを間違えている。「現在の運転点で測った FEM/スラブ法の比」で補正した逆解は、
**同じ運転点なら定義上必ず一致する**ので往復テストが通ってしまい、離れた点で最大 +60% ずれた。
いまは閉じたモデルをそのまま二分しているので、運転点の概念自体が無い。

```
 P = 2253.6 tonf（h 2.0->1.2 を μ 0.0600 で圧延したときの荷重）
 h 2.0->1.2 に対して解く : μ 0.060000  (dP 0.0e+0 %)   ← 作ったときの μ に戻る
 h 2.0->1.5 に対して解く : μ 0.143981  (dP 2.2e-14 %)  ← 別のパスなので別の答え、
                                                          ただしその荷重は厳密に再現する
```

同じ荷重でも別のパスなら別の μ になり、**どちらも自分の荷重を厳密に再現する**。これが
「補正係数」実装との違い。

### 感度 — 打ち切りを緩められない理由

`d ln P / d ln μ` と、括弧内は「荷重 1% の誤差が μ の何 % になるか」。

```
 μ =                              0.02          0.05          0.10          0.20
 h 2.0->1.5, R 190, 連成 ON   0.080 (12.6%)  0.218 (4.6%)  0.524 (1.9%)  2.390 (0.4%)
 h 2.0->1.5, R 190, 連成 OFF  0.057 (17.6%)  0.146 (6.9%)  0.304 (3.3%)  0.658 (1.5%)
```

低摩擦側ほど悪い。冷間の常用域（μ ≈ 0.05）で **荷重 1% ＝ μ 4.6%**、μ = 0.02 なら 12.6%。
「荷重が 1% 合っていれば十分」は成り立たないので、二分は倍精度の最終ビットまで回す
（55 回前後、閉じた式なので費用は無視できる）。
ロール弾性連成を入れると接触弧まで荷重とともに伸びるため感度はさらに上がる。

### 出せる荷重には下限がある

μ → 0 でも摩擦丘が消えるだけで `kf*·L` は残るので、荷重はそこまでしか下がらない。
上側は逆に、あるところでロール扁平が発散して定常解が無くなる（Stone の最小圧延可能板厚）。
どちらも数字を返さず理由を返す。

```
 h 2.0->1.5, σ 0/0        μ 0.005 -> 1143 tonf    μ 1.0 -> ロール扁平が発散
 h 2.0->1.5, σ 30/60      μ 0.005 -> 1063 tonf    μ 1.0 -> ロール扁平が発散
 h 2.0->1.8, σ 0/0        μ 0.005 ->  599 tonf    μ 1.0 -> ロール扁平が発散
```

既定のまま（h 2.0→1.5, 張力 0, 目標 1040 tonf）押すと下限 1143 tonf を下回るので解けない。
これは仕様どおりで、メッセージが下限値を出す。

### ブラウザ上の確認

`?stands=3` で 3 スタンド、出側板厚 1.5 / 1.15 / 0.92 mm、σb 30/60/55、σf 60/55/20 MPa、
R 190/190/150 mm、荷重 1222/1527/1350 tonf を表に入れて「μ逆算」を押した結果:

```
 #1  μ 0.04052  h 2.0000->1.5000 mm  R' 267.3 mm  kf  740 MPa  照合 1222.0 tonf (誤差  0.0e+0 %)
 #2  μ 0.03182  h 1.5000->1.1500 mm  R' 328.0 mm  kf 1000 MPa  照合 1527.0 tonf (誤差 -1.6e-14 %)
 #3  μ 0.03095  h 1.1500->0.9200 mm  R' 296.6 mm  kf 1125 MPa  照合 1350.0 tonf (誤差  1.8e-14 %)
```

- `kf` が 740 → 1000 → 1125 MPa と段ごとに上がる。前段までの加工硬化を引き継いで、
  **その段が自分で加えるひずみ区間**で平均しているため。ここを 0 から平均すると 3 段とも
  740 MPa になり、2 段目以降の荷重を系統的に読み違える。
- `R'` は Hitchcock の不動点で、削り半径の 1.41 / 1.73 / 1.98 倍。冷間で R ではなく R' を
  使う理由がそのまま出ている。
- 表の μ 欄は赤で表示され、入力を変えると取り消し線に変わる（自動では解き直さない）。

### 逆算した μ を入れた FEM は入力荷重にはならない

これは仕様であって不具合ではない。逆算が一致させるのは**スラブ法の荷重**で、FEM の荷重ではない。
`?stands=1&agc=off&mesh=fast`、h₀ = 2 mm、圧下率 25% 指令（制御 off なのでギャップは指令位置で固定、
出側は扁平ぶん開いて h₁ = 1.5881 mm）、張力 0、板幅 1300 mm。ブラウザ上で整定を待って測った値:

```
 押す前          μ 0.06000   FEM 荷重 987.0 tonf
 目標 1165 tonf  μ 0.04963   FEM 荷重 963.1 tonf   （スラブ法では 1165.0 tonf, 誤差 0.0e+0 %）
 目標 1806 tonf  μ 0.14568   FEM 荷重 1129.3 tonf  （スラブ法では 1806.0 tonf, 誤差 -1.4e-14 %）
```

- **μ は確かにソルバまで届いている** — μ を下げれば FEM 荷重も下がり、上げれば上がる。
  1 回目の測定値は `d ln P / d ln μ = 0.129` で、このモデルの感度としてほぼ既知値どおり。
- **荷重は一致しない** — FEM/スラブ法比は既知のとおり 1 を下回り、ここでは 0.83（μ 0.050）→
  0.63（μ 0.146）。スラブ法は均一圧縮を仮定するので摩擦丘が立つほど過大評価する
  （「圧下率スイープ」「摩擦スイープ」と同じ性質）。
- したがって **1 回目のように「荷重を上げたのに μ が下がる」ことがある**。この運転点では
  スラブ法が μ 0.06 で 1165 tonf より重い荷重を出すので、1165 tonf にするには μ を下げる側に
  なる。逆算は自分のモデルに対して正しく、そのモデルと FEM の差は別の話。

実測荷重から μ を推定する道具として使うなら、この差を承知の上で使うこと。FEM の荷重に
一致させたいなら、μ を動かして FEM を毎回整定させる別の探索が要る — それは時間方向の
反復になるので、この機能の要件（押した瞬間に 1 回だけ）とは別物になる。

## 保留（gaugeIdle）判定とミルスプリングの過渡値

**測定条件** — 現在の既定（冷間圧延 (薄板) プリセット）を `?stands=3&mesh=fast` で 3 スタンド、
全段 出側板厚一定（gauge）。板幅 1300 mm。ブラウザ上で整定を待って測った値。
サンプリングは**アニメーションフレーム単位**（ページ内で `requestAnimationFrame` から採取）。
CDP 越しの 100 ms ポーリングでは下の過渡は 1 フレームしか無いので取りこぼす。

### スクリューを動かした直後 1 フレームの `h₁ − S` はスプリングではない

`springHeld`（保留判定の床 = 入側 − スプリング に使う値）は `h₁ − S`。目標を打ち直すと
`retarget()` がスクリューを飛ばすが、出側板厚はまだ動いていない。#3（入側 1.2035 mm、
整定スプリング 0.0744 mm）で目標を 0.9174 → 0.25 mm に打ち直したときの各フレーム:

```
 frame 0  h1 0.9182  S 0.8438  spring 0.0744  床 1.1291   ← 静定
 frame 1  h1 0.9182  S 0.3610  spring 0.5571  床 0.6463   ← ギャップだけ飛んだ
 frame 2  h1 0.4332  S 0.3610  spring 0.0721  床 1.1313   ← 出側が追いついた
```

frame 1 の 0.5571 mm は整定値の **7.5 倍**。床は 1.1291 → **0.6463 mm** に落ちる。
0.65〜1.20 mm は普通に圧延できる目標の帯なので、この 1 フレームに目標がその帯にあると
`gaugeIdle` が真になり `Mill.advance` がスタンドを止める（＝保留）。保留中は接触が無いので
`springHeld` が更新されず、**間違った床のまま復帰できない**。

### 対策と、その効果

`springHeld` を「**ギャップと出側板厚のどちらも動かなかったフレーム**」でのみ更新する
（しきい値 `SPRING_STILL = 2e-3`、相対、フレーム間）。同一手順の A/B:

| | frame 1 の spring | frame 1 の床 | 全区間の spring 最大 | 全区間の床 最小 |
|---|---|---|---|---|
| 対策前 | 0.5571 mm | 0.6463 mm | 0.5571 mm（整定比 7.5×） | 0.6463 mm |
| 対策後 | 0.0743 mm | 1.1293 mm | 0.0780 mm（整定比 1.0×） | 1.1257 mm |

収束後の値は変わらない（対策前 h₁ 1.0398 mm / 709 tonf、対策後 h₁ 1.0401 mm / 694 tonf。
差は整定判定のタイミングによるもので、スプリング自身は両者とも 0.074 mm 付近に戻る）。

### 表示

保留の判定は入側板厚ではなく床（入側 − スプリング）に対して行う。以前のラベル
「保留（目標 ≥ 入側板厚）」は判定式と違うので、**入側より薄い目標でも保留になる**ケースが
説明できていなかった。実測:

```
 入側 1.2035 mm  床 1.1205 mm  目標 1.1620 mm  → 保留
```

現在は AGC パネルに「保留（目標 1.1620 ≥ 圧下下限 1.1205 mm）」と判定に使った 2 つの数字を
そのまま出し、ミルライン図は「保留（圧下にならない目標）」と表示する。

また保留の判定はソルバを回さなくても答えが出る（目標・入側・スプリングだけ）ので、
**一時停止中も生きた値**を表示する。以前は最後に解いたときの値を出していたため、
停止中に目標を打ち直すと — スクリューは動くのに — 判定だけが打ち直す前のままだった。

### 目標がスクリュー下限を下回るときは「張り付き」であって保留ではない

（測定当時 `sepFloorFrac = 0.30`。現在の既定は 0.05 — 下記「スクリュー下限を 30% から 5% に」参照。）
バレル間隔（＝ほぼ出側板厚）の下限は入側の 30%。
#3 の入側 1.2035 mm なら 0.3610 mm で、**目標 0.25 mm は構造的に届かない**。

```
 目標 0.2500 mm  →  S 0.3610 mm（下端に張り付き）  h₁ 0.5416 mm  荷重 2289 tonf  agcSaturated=true
```

目標そのものは `agcSetpoint` まで 0.2500 mm で正しく届いており、届かないのはスクリューの
下限のため。状態は「ギャップ端に張り付き」。スタンド表の「出側板厚 現在」セルにも
理由をツールチップで出す（下限値と入側板厚を添える）ので、選択中スタンド以外でも分かる。

## ギャップ制御の収束精度 — 不感帯の既定を 1e-4 → 1e-6 に

**測定条件** — 現在の既定（冷間圧延 (薄板) プリセット）、`?stands=1&mesh=fast`（板 70×6）、
板幅 1300 mm、割線法、`agcEvery 4`、`agcMaxStep 0.02`。整定は「ループ自身の `agcSettled` が
連続 8 回（3.2 s）真」で判定し、固定待ちは使っていない。整定時間はステップ入力からその時点まで。

### 何が残差を決めていたか

ループは偏差が**初めて不感帯に入った瞬間に止まる**。残る誤差は帯の中のどこかで、
既定 1e-4（0.01%）では 6 ケースの残差が 1.8e-3〜9.8e-3 % にばらついていた —
つまり**結果の精度 = 不感帯の値**であって、解の精度ではなかった。

一方で止めたループの周りでプラントがどれだけ揺れているか（不感帯が本来競合している量）:

```
 mode    |err| mean    ptp(40 s)     h₁ ptp     P ptp        余裕（帯/ptp）
 gauge   5.26e-3 %    1.94e-8 %    0.000 µm   0.00 tonf    5×10⁵
 ratio   3.95e-3 %    5.46e-6 %    0.000 µm   0.00 tonf    1800
 force   9.40e-3 %    3.95e-4 %    0.003 µm   0.00 tonf    25
```

帯はノイズの 25〜500,000 倍上にあった。締めても失うものは整定時間だけ。

### 不感帯を締めたときの整定時間と残差

```
 case                     1e-4（旧既定）        1e-6（新既定）         1e-7
 ratio  25→35 %           7.6 s / 8.0e-3 %     10.0 s / 8.4e-5 %     12.8 s / 5.1e-6 %
 ratio  35→20 %          10.7 s / 2.2e-3 %     11.6 s / 9.2e-5 %
 gauge  1.50→1.30 mm      8.7 s / 1.8e-3 %      9.8 s / 7.2e-5 %     12.4 s / 7.5e-6 %
 gauge  1.30→1.60 mm      9.7 s / 4.3e-3 %     12.0 s / 7.0e-5 %
 force  900→1300 tonf    12.8 s / 7.9e-3 %     21.4 s / 9.1e-5 %     25.7 s / 1.5e-7 %
```

1e-6 で残差 2 桁改善、整定時間は 1.1〜1.7 倍。1e-7 も 3 モードとも届く。
**壁は 1e-8**: 荷重制御は 60 s かけても帯の 2 倍（2.1e-6 %）で止まる。

### 自走速度ループの刻みを適応させる案も不採用

反力の符号が反転するたびに速度ステップの上限を半分にする（扁平連成の `relaxScale` と同じ規則）
案。後述のリミットサイクルに対して反転回数 204 → 123 回/2000 フレームと減るが止まらず、
通常の過渡では**逆に遅くなる**（圧下率 25→35% の整定 10.0 s → 24.8 s）: 減衰振動の反転で
刻みが縮み、その後 4 フレームごとのスクリュー移動に追従できなくなる。

### 測定値の平滑を長くする案は不採用

荷重は接触列の出入りによるリプルを持つ（上表の force ptp 3.95e-4 %）ので、一次遅れの
係数 α（既定 0.25）を下げれば見える誤差の床が下がると考えて試した。**両軸で負け**:

```
 band 1e-6  α 0.25: 21.4 s / 9.1e-5 %      α 0.08: 39.7 s / 7.8e-6 %
 band 1e-7  α 0.25: 25.7 s / 1.5e-7 %      α 0.08: 29.8 s / 3.6e-6 %
```

α を下げると測定が遅れて割線法の感度同定が鈍り、帯に入るまでに要する手数が増える。
帯を締めるだけのほうが速くて正確なので、この係数は露出しない。

### スライダ範囲

- 不感帯の下限を 1e-5 → **1e-8** に。旧下限はプラントが出せる精度の 2 桁上で、
  ループが到達できる精度をパネルから要求できなかった。
- 自走制御 不感帯の下限を 5e-4 → 1e-4 に。**既定 3e-4 が旧下限より小さく**、
  スライダに触れるだけで 1.7 倍緩む状態だった。

## 接触列の出入りによるリミットサイクル（`contactToggling`）

> **この節の現象は根治した** — 板メッシュの列を噛み込み入口に追従させ、接触集合を固定にした
> （下の「噛み込み入口にメッシュ列を追従させる」）。`contactToggling` の検出と表示は削除。
> 以下は等間隔メッシュ時代の記録。

**測定条件** — 同上、`?stands=1`。制御 **off**、圧下率指令でスクリューを gap 1.5606 mm
（21.97%）に固定。フレーム単位で採取。

荷重一定モードの整定が同条件で 21 s だったり 90 s 超だったりした原因。制御ループを
すべて外し、二分した結果:

```
 条件                             荷重 [tonf]     接触列    質量収支          判定
 off, 連成 ON                     853–944 (±5%)   19↔20    1.004↔1.019       鳴る
 off, 剛体ロール                  874 一定         19       1.0041            静か
 off, 連成 ON, 速度固定 0.935      825–914          19↔20    1.005↔1.019       鳴る
 off, 連成 ON, 弾性域 OFF          865–953          19↔20    1.006↔1.021       鳴る
```

発振器は**ロール扁平 ↔ 接触列の出入り**。噛み込み入口が板メッシュの列境界に乗ると、
その列が接触に入る → 荷重が上がる → 入口でロールが扁平して h₀/2 より浮く → 列が抜ける →
荷重が下がる → また入る。接触の組み立て（`flow.ts`）は列ごとに二値で、被覆率 `contactWeight`
は荷重積分にしか使われていないため、列 1 本の出入りが速度場全体を跳ばす（質量収支 1.5% の跳び）。
ゲイン・不感帯・平滑・速度ループの刻みでは止まらない — ループの外で起きている。

### メッシュ細分は段を動かすが消さない

`stripNx/Ny` を直接変えて再構築（**`?mesh=` はクエリとして読まれていない**ので、
それを使った比較は無効）:

```
 板メッシュ   gap 1.5606 mm（制御 off）                  gap 1.289 mm（荷重一定 1300 tonf）
 100×8        850–940 tonf (±5%)  19↔20  mass 1.004–1.019
 140×10       静か                                       —
 200×14       872 ±0.4 tonf (0.04%)  41 固定  mass 1.0010   1226–1316 tonf (±3.5%)  49↔50
 300×20       873 ±0.0             62 固定  mass 1.0011
```

200×14 は 1.5606 mm では静かだが、同じメッシュで荷重一定 1300 tonf に向かうと gap 1.289 mm で
別の列境界に乗り ±3.5% で鳴る。細分は列境界の位置を変え段を低くするが、境界そのものは
どのメッシュにもある。計算コスト（ヘッドレス SwiftShader）: 100×8 3.2 ms/frame（50 fps）、
140×10 7.4 ms（35 fps）、200×14 13.7 ms（25 fps）。

### 解そのものを入口位置で連続にする試み — 2 案とも却下

1. **摩擦トラクションを被覆率で重み付け**（荷重積分と整合させる）: 段は消えず（ptp 91 → 82 tonf）、
   既定運転点の先進率が 2.04 → 1.71%（−16%）に動いた。
2. **拘束法線を被覆率で自由表面法線とブレンド**（拘束は 1 本のまま向きだけ連続化）:
   gap 1.5606 の段は消えた（851 tonf 一定、mass 1.0027）が、既定 25% 圧下が壊れた
   （P 987 → 829〜869、先進率 −9.7〜−11.4%、中立点なし、質量収支 0.888〜0.908、未収束）。
   入側列の被覆率 0.476 の 1 節点の法線を ~1° 回しただけでこうなる。

つまり入口 1 列の扱いに解が ±10% の感度を持っており、これは既定 100×8 における荷重の
離散化不確かさでもある。

### 処方

- **検出**: 入口列 `contactFrom` が 180 フレーム内に 4 回以上変わったら `contactToggling`。
  AGC パネルの状態が「接触列が入口で出入り（離散化）」になり、スタンド表の「現在」セルにも
  ツールチップで出る。100×8・gap 1.5606 で真、140×10・200×14（同ギャップ）で偽を確認。
- **回避**: 目標をわずかにずらして入口を列境界から外す。必要量は
  `Δh₁ ≈ dx_col / (½√(R'/Δh))`（1 列ぶん。既定条件で ≈ 35 µm、半分で外れる）を
  パネルに実測値から表示する。
- 既定メッシュは変えていない（検証済みの数値がすべて 100×8 のため）。

「収束」と「ギャップ端に張り付き」が同時に出ることがあった。`agcSaturated` は直前のスクリュー移動が
レールに当たったときに立ち、`agcSettled` 分岐に到達したときだけ下りる — ライン保持（`holdGap`）や
速度ループ待ちで早期 return するスタンドはその分岐に来ないため、偏差が帯に入ったあとも旗が残った。
偏差が帯に入った時点でゲートより前に下ろすよう変更。3 スタンド圧下率一定を 70 s × 2 回、
0.2 s ごとに監視して `settled ∧ saturated` は 0 回（変更前の再現は待機点依存で確率的）。

## 保留の判定を「目標 ≥ 入側の現在値」に

**測定条件** — 既定条件、`?stands=1`、出側板厚一定、100×8。

床を「入側 − ミルスプリング」にしていた判定は、スプリングが荷重の関数であることを無視していた
（重い圧下のスプリング 105 µm を軽い圧下に当て、3% 圧下＝37 µm の目標を保留にする）。
「メッシュで解ける最小圧下量 (3·dx)²/R′ ＝ 6.5 µm（0.33%）」を床にする案は、実際の数値限界が
それより重いことが分かり却下:

```
 目標      圧下率   整定   h₁        接触列   状態
 1.9400    3.00%    ○      1.9400      8     収束（33 s）
 1.9800    1.00%    ×      1.9736      6     内側ループ待ち（60 s）
 1.9900    0.50%    ×      1.9765      5     内側ループ待ち
 1.9980    0.10%    ×      1.9765      5     内側ループ待ち
 2.0020   −0.10%    —      2.0000      0     保留（目標 2.0020 ≥ 入側 2.0000 mm）
```

採用した判定は「丸める前の目標 ≥ 入側板厚の現在値」のみ。軽すぎて解けない目標は保留にせず、
「噛み込みが浅すぎて解けない（圧下 X%・接触 N 列）」（目標圧下率 < 2% かつ停止中）として報告する。
同じ 1% 目標が別の回に接触 7 列・h₁ 1.9552 で止まったので、接触列数ではなく目標圧下率で判定する。

## タンデムの直列整定 — 「前段が終わるまで動かない」の原因と修正

**測定条件** — 既定条件、`?stands=3&agc=ratio`、100×8。起動から 0.25 s ごとに採取。

```
                         #1 初動  #1 整定  #2 初動  #2 整定  #3 初動  #3 整定

 保持だけ OFF               0.5     16.0     17.8     25.4     33.4    never   ← 初動は変わらない
 速度コーン OFF（保持 OFF）  0.5     16.0      4.1     21.5      0.5    never   ← ここで初動が早まる

```

#2 のゲートを見ると、起動から 16 s のあいだ送り反力残差が μP の 60%（feedRes 0.6）で、

速度コーンは目標出側板厚（圧下率一定・板厚一定）から周速を決めるよう変更（実測板厚だと
自己ループ）。

残課題: #3 が目標付近で ±0.25 µm（偏差 ±1e-2 %）のハンチングを続け、不感帯 1e-6 に入らない。
速度コーン OFF でも同じで、変更前から存在する。

## 噛み込み入口にメッシュ列を追従させる — 接触列の出入りの根治

**測定条件** — 既定条件（冷間圧延 (薄板)、R = 190 mm、h₀ = 2 mm、25%、μ = 0.06、板幅 1300 mm）、
`?stands=1&mesh=balanced`（板 100×8）、制御 **off**。以下「#3」は `?stands=3&agc=ratio` の

### 何が壊れていたか

上の `contactToggling` 節の通り、噛み込み入口が列境界に乗ると接触集合が 1 列出入りして荷重が
±5% で鳴る。荷重一定ではその段の中に目標が入り、原理的に収束しない:


入口列の被覆率にヒステリシス（0.35 で入り 0.05 で抜ける）を付ける案は、制御 off の鳴きは止めた
（gap 1.5606 で 875 tonf 一定）が、荷重一定ではループがヒステリシス帯を自分で往復した
（スクリュー ±6 µm、荷重 995〜1121 tonf）。却下。

### 設計

- 列位置は毎フレーム、`winIn → 入口 → 0 → winOut` の 3 区間に区分線形で配る。入口列 `iE` と
  出側列 `iX` の番号は組み立て時に公称弧長から決め（`fitColumns`）、弧が 1.6 倍以上伸び縮み
  したら配り直す。接触集合は `[iE, iX]` 固定。
- 入口の交点（バレルが h₀/2 を切る x）は緩和済みロール変位そのものから毎フレーム二分法で求める。
  板の表面高さに使う列ごとのバレル高さは、その上にもう一段の低域通過（`rollRelax·relaxScale`）
  — これは**扁平ループの減衰**で、外すと入出側弾性 OFF で発振する（下の節）。列がイベントで
  動いたときは旧位置から補間して記憶を引き継ぐ。
- 入口節点の拘束は半径方向ではなく**両隣の面の平均勾配に沿う流線条件**、摩擦は負担長の半分。
- 入口列を交点へ置き直すのは**スタンドが静かなフレームだけ**（速度ループが自分の帯の中、かつ
  ギャップループが収束か制御なし）。置き直したら 60 フレームは動かさない。交点から 0.05 列以上
  離れているときだけ無条件に 1 フレーム 0.1 列で追う。0.005 列未満のずれは放置。
- 荷重一定 × FEM 荷重の不感帯は `max(設定値, 2.5e-3)`（`MESH_QUANTUM`）。

### Hitchcock 不動点の反復を有界に

Orowan で #3 に張力 50 MPa を与えると不動点が「無い」扱いになり、その 1 評価が 4000 回の反復を
回して **1 フレーム 1.13 s**（`stepMs`）— スラブ法モード 3 スタンドが 1 fps 未満に落ちて全ループが
崩れた（起動から 90 s、全段スクリュー不動、h₁ ptp 47〜68 µm）。原因は 2 つ: 固着境界 a → 1 で
w(a) の勾配が無限大になり、p を求める不動点反復が収まらないこと（固着解 p = q + w(1)kf を先に
試し、滑りのときだけ反復する形に）と、上限 4000 回・R′ 上限 10⁴R が数値積分の式には重すぎること
（上限 400 回・100R、刻みが 5 回連続で伸びたら発散扱い、収まりつつあれば打ち切り値を採用）。
kf(φ) も RK4 の段で毎回 pow() していたのを半刻み格子で 1 回に。修正後の #3・張力 50/50:
Orowan P 2244.3 / R′ 442.4 mm、B&F 2238.8 / 441.8。R′ を 200〜1200 mm で振った写像
`R(1 + C·P(R′)/Δh)` は 3 式とも 400〜450 mm で対角線を一度だけ切る。

## ロール偏平の式 — Hitchcock ／ Roberts

**測定条件** — 上の 3 式の表と同じ（既定条件、`?stands=1`、h₁ = 1.5855 mm、FEM P 959.1 tonf、
FEM の R′ 263.2 mm）。`?flat=roberts`。

実装した Roberts の式: `L = b + √(b² + RΔh)`, `b = √(4(1−ν²)PR/(πE))`（Hertz の接触半幅）,
`R′ = L²/Δh`。Hitchcock は `R′ = R(1 + 16(1−ν²)P/(πEΔh))` ⇔ `L² = RΔh + 4b²`。圧下ゼロで両式とも
`L = 2b`。**b の係数は原著の読みで置いており、出典と照合のこと**（`muinv.ts` `flatRadius` の 1 行）。

```
                Bland & Ford    1259.8      286.1        1584.1      413.6    1.257

                Orowan          1129.7      276.2        1404.7      396.1

                Orowan           979.7      264.8        1229.4      378.4
```

Roberts は既定運転点で弧 12.1 mm（Hitchcock 10.5、FEM 8.9）、R′/R 2.15（Hitchcock 1.49、FEM 1.39）、

## 入出側弾性 OFF の発振 — 扁平ループの減衰を落としていた

**測定条件** — 既定条件、`?stands=1&agc=gauge`（板厚一定 1.5 mm）、`elasticZones` を `__lab.setParam` で
切替。3 スタンドは `?stands=3&agc=ratio`。

追従メッシュを入れた際、列ごとのバレル高さの低域通過（`barrelY`、`rollRelax·relaxScale`）を
「動く列の上では別の場所の記憶」として外していた。ON では気付かなかったが OFF で発振:

```
                 ON（弾性域あり）              OFF（純粋剛塑性）
 荷重 P          1112 tonf で静止             3149 → 4093 → 375 → 4120 tonf を往復
 h1              1.50003（18 s で整定）        1.55〜1.64
 先進率          2.09%                        5.2〜5.9%

 couplingResidual 0                            0 ↔ 1.2e-2（減衰係数が反転のたびに発火）
 3 スタンド       全段整定                      全段 never、停滞 99%、h1 ptp 24 µm
```

CG は収束（残差 1e-17）。入口節点の拘束を半径方向に戻しても同じ（P 32 ↔ 4770）— 拘束ではない。
往復しているのは **荷重 → 扁平 → ギャップ → 荷重** の連成ループ。ロール変位の緩和（`rollRelax`）は
残っていたが、板表面が読むバレル高さの二段目の緩和が無く、減衰が半分になっていた。OFF は
体積ペナルティが ON の K·t の約 20 倍硬く（1e4·μ_ref 対 K·t ≈ 540·μ_ref）、荷重がギャップに対して
それだけ鋭いので、一周利得が 1 を超えて 2 状態を往復する。ON は柔らかいぶん利得が 1 未満で
たまたま収まっていた。

修正: 低域通過を戻し、列がイベントで動いたときは旧位置から線形補間して記憶を引き継ぐ
（`updateGap` Pass 1）。結果:

```
                          修正前                修正後
 OFF 1 スタンド            往復                   963.98 tonf で静止、picard → 0
 OFF 3 スタンド圧下率一定  全段 never             18.8 / 21.4 / 32.5 s
 ON  既定運転点            959.14                 959.22（不変）
 ON  3 スタンド圧下率一定  13.9 / 16.8 / 59.9 s   5.2 / 11.8 / 14.4 s

 ON  FEM 荷重一定          7.9 / 75.8 / 80.5 s    2.7 / 29.1 / 28.6 s
 ON  スラブ荷重一定 Kármán 13.5 / 30.3 / 47.0 s   7.7 / 21.0 / 32.5 s
```

減衰が戻ったぶん ON の整定も 2〜3 倍速くなった — 追従メッシュ導入後の遅さの半分はこれだった。
OFF の荷重 964 は ON の 959 と 0.5% 差（弾性回復ぶん）で、旧等間隔メッシュの「OFF 990 / ON 987」と
同じ関係。

## ロール弾性連成 OFF で荷重が変わらなかった

**測定条件** — 既定条件、`?stands=1`、制御なし、スクリュー 1.500 mm 固定。ON で 25 s 走らせてから
`rollCoupling` を切り、20 s 後に戻す（`toggletest.mjs`）。

**原因 1（修正済み）: 接触節点の法線が無変形の円の半径方向だった。** 板表面のメッシュは扁平・低域通過・
単調化済みの実バレル形状に敷かれる（`updateGap`）のに、速度拘束 v·n = 0 の n は `rollCx, cy` からの半径方向。
R′ = 1.4 R の扁平で両者の勾配は中央で 4 %、出口面では円が水平なのにメッシュは −0.4 % で下っており、
`__lab.streamline(k)`（列ごとの v_y − v_x·s′）で流線残差が v_x の 0.5 % に達し、その累積が流量分布の山
（+0.8 % / +1.6 %）と一致した。接触節点の法線・接線と面圧回復の法線をメッシュ表面勾配（自由表面と同じ流線条件）に
変えると流線残差は全列で 0 になり:

| 3 スタンド 板厚一定 | #1 | #2 | #3 |
|---|---|---|---|
| 修正前 | 0.9957 | 0.9926 | 0.9956 |
| 法線修正後 | 0.9974 | 0.9964 | 0.9957 |

荷重は +0.5 %（1077 → 1082 tonf）、先進率は #1 2.67 → 2.98 %、#3 3.2 → 5.2 %（出口で漏れていた分が出側速度に戻った）。
板厚一定・荷重一定・圧下率一定・張力制御併用・制御なしの 5 ケースで 3 段とも整定。

**原因 2（記録のみ）: 弾性域の体積項が体積「粘性」で、圧縮はするが戻らない。** 法線修正後の流量分布は
噛み込み内で静水圧（−300〜−540 MPa）に応じて 0.28 % 減り（p/K = 500 MPa / 175 GPa と一致）、出口で圧力が 0 に
戻っても 0.9974 までしか戻らない。`kBulk = K·t_ref` は p = −K_v div v の粘性項なので、流線に沿った正味体積変化は
−(1/K_v)∫p dt で状態量ではない。体積項を常に非圧縮ペナルティにすると保存される（1e4·μ_ref で 0.9998〜0.9999）が、
下流段の 荷重 → 扁平 → ギャップ 連成ループの利得がこの剛性で決まり:

| kBulk / μ_ref | 質量収支 (#1/#2/#3) | 安定性 |
|---|---|---|
| K·t ≈ 175〜540（既定） | 0.9974 / 0.9964 / 0.9957 | 全モード整定 |
| 1000 | 0.9988 / 0.9983 / 0.9980 | 板厚一定・張力併用は整定、荷重一定は #2/#3 が整定しない |
| 1500〜2000 | 0.9992〜0.9994 / … | 板厚一定は整定、張力併用の板厚一定で #3 暴走、荷重一定 ✗ |
| 4000〜1e4 | 0.9997〜0.9999 | 板厚一定は 4000 で整定、圧下率一定・荷重一定・張力併用は暴走、1e4 は NaN |

既定は K·t のまま。根本解は「戻る」体積状態量（圧力を輸送する弾性定式化）か、扁平連成の減衰強化。

**解法で嵌ったところ**（同じ失敗を繰り返さないための記録）

1. *Hitchcock の暖機始動*: 前回の q から R' を始めると、写像の外側の偽の不動点に乗って荷重が
   発散 → 次のスライス反復で 0 → 交互に振動した。2D タブの `muinv.ts` と同じ教訓で、毎回 R'=R から
   Newton で登る（凸なので越えない）。
2. *張力の局所ループ*: 張力 → 局所荷重 → WR 扁平 → 板厚 → 伸び → 張力 の利得が −20 前後。
   ロール位置の Newton に「張力は板厚の関数」として対角に入れると、一様な沈み込みモードの剛性を
   50 倍に見誤って動かなくなる（平均拘束の rank-1 項で相殺すべきもの）。遅延させれば発振。
   固定ロール位置で張力を陰的に解き、その全微分を Woodbury で外側に渡すのが正解だった。
3. *クランプの半滑らか Newton*: 座屈・降伏の頭打ちを softplus で丸めても、限界に張り付いた
   スライスの傾き 0 の行が残差ぶんを一気に踏み、反対の限界へ飛んで集合が毎回裏返る。
   能動集合法（張り付いたものを固定して残りを Newton、集合を見直す）で 1 ラウンド 2〜4 反復に
   落ちた。解放条件は「自由応力がその限界の側から離れたら」— 反対の限界を越えていても
   解放しないと λ（平均を保つオフセット）が 8 GPa まで走った。
4. *接触ブロックの二重加算*: 帯行列は下三角しか持たないので、節点内の (v, w) 交差項は 1 回、
   節点間ブロックは 4 項全部。縦積み（法線が鉛直）では出ず、クラスタで Cholesky が落ちて発覚。
5. *サドル剛性*: ハウジング剛性を 7 点で割ると 20Hi のバッキング軸が 370 µm 浮いてクラウン
   170 µm。剛性は「支持点あたり」の意味にした。
6. *スクリューの下限*: AS-U +200 µm でスタックが予圧されると S=0 でもう 20% 圧下を超えており、
   S≥0 の締め付けでは目標に届かず 1200 反復回った。開き（負）を許す。
