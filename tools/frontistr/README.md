# FrontISTR との照合

3D タブのロールスタックモデル（ティモシェンコ梁 ＋ 線接触の扁平）を、同じロールを 3 次元ソリッド要素で解いた
FrontISTR（オープンソースの汎用 FEM）の解と突き合わせる道具。アプリの計算は変えない。

## 何を比べるか

板の荷重 q(x)（スラブ法のスライスが収束させた値）を**両方に同じだけ与える**。ロールモデルが扁平に使う Hertz の
半幅 b(x) の上に半楕円の圧力として掛け、軸受はロールモデルと同じ x = Ls/2 の断面を y に固定する（2 点支持の梁は
静定なので、たわみの形は軸受の剛性に依らない）。違いはロールの力学だけになる:

- **軸のたわみ** v(x) − v(軸受): ネックの段付きと点支持を持つ梁 vs ソリッド
- **扁平**（板の下の局所的な沈み込み）: 線接触の近似式 vs ソリッド表面の押し込み。ソリッドでは曲げのポアソン効果
  （−ν κ R²/2、上下の表面で同じ）が「表面 − 軸」に混ざるので、**下面 − 上面**で読む（2Hi は上面に荷重がない）

## 使い方

FrontISTR は Homebrew の gcc・open-mpi・metis・openblas で自前ビルドする（並列なし・OpenMP あり・MUMPS なしの最小構成で
`~/.local/bin/fistr1`。Xcode のライセンス同意が要る）。

```bash
brew install gcc open-mpi metis openblas cmake
git clone --depth 1 https://github.com/FrontISTR/FrontISTR.git ~/Software/FrontISTR && cd ~/Software/FrontISTR && mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc-16 -DCMAKE_CXX_COMPILER=g++-16 -DCMAKE_Fortran_COMPILER=gfortran-16 \
  -DWITH_MPI=OFF -DWITH_OPENMP=ON -DWITH_METIS=ON -DMETIS_INCLUDE_PATH=/opt/homebrew/opt/metis/include -DMETIS_LIBRARIES=/opt/homebrew/opt/metis/lib/libmetis.dylib \
  -DWITH_MUMPS=OFF -DWITH_ML=OFF -DWITH_LAPACK=ON -DBLAS_LIBRARIES=/opt/homebrew/opt/openblas/lib/libopenblas.dylib -DLAPACK_LIBRARIES=/opt/homebrew/opt/openblas/lib/libopenblas.dylib \
  -DWITH_REFINER=OFF -DWITH_TOOLS=ON -DCMAKE_INSTALL_PREFIX=$HOME/.local
make -j4 && make install
```

```bash
node tools/build-esm.mjs sim3d
node tools/frontistr/case.mjs 2hi                 # 2Hi 既定（関門の格子 81/0/8）を解き、tools/frontistr/run/2hi/ に roll.msh・roll.cnt・hecmw_ctrl.dat・reference.json
tools/frontistr/run.sh tools/frontistr/run/2hi    # fistr1（節点 3.4 万、線形、CG、約 16 s）
node tools/frontistr/compare.mjs tools/frontistr/run/2hi
node tools/frontistr/case.mjs 4hi                 # 4Hi 既定: WR ＋ BUR、接触（拡張 Lagrange、摩擦 0）、荷重 4 分割
tools/frontistr/run.sh tools/frontistr/run/4hi    # 節点 9.2 万、非線形、26 分（Apple M2、OpenMP 4 スレッド、他の計算と重ねて）
node tools/frontistr/compare.mjs tools/frontistr/run/4hi
```

`case.mjs <mill> [outdir] ['{"param":value}']` で条件を変えられる（`Params3D` のキー）。`run/` は git 管理外。各 `run/<mill>/compare.txt` に表の写し。

## アプリ内から（4Hi）

`npm run dev` の開発サーバーが同じ照合を `/__frontistr` で受ける（`vite.config.ts` が `bridge.mjs` を組み込む）。
3D タブで「解析・表示 ▸ ロールの照合」を **FrontISTR** にすると、計算が収束するたびに今の条件でケースを作って
`fistr1` で解き:

- 「ロール撓み」に WR・BUR の軸の FEM 曲線、「接触線荷重」に WR–BUR の線荷重、「板厚プロファイル」に出側プロファイルを白の破線で重ねる
- 右パネル「FrontISTR 照合」に、板中央の各ロールの撓み・WR–BUR の線荷重のモデル／FEM、最大差（括弧はモデルの最大値に
  対する比）、軸受反力（FEM）と板の荷重、節点数と所要時間
- 上のチップ「FrontISTR」に WR 中央の差と最大相対差

条件を変えると結果は消え、次の収束でまた解く。3D タブは 2026-09-19 から 4Hi だけなので、アプリから解くのは 4Hi だけ。
橋渡し（`bridge.mjs`）は 2Hi・6Hi のケースも今までどおり組める（上の `case.mjs` と同じ。12Hi・20Hi のクラスタは未対応: 斜めに
並ぶバッキングベアリングとサドルの接触は別の仕事）。板は関門と同じ「ロールの節点に載せる・弧 8 分割」に固定し、
それ以外の条件（寸法・クラウン・板・荷重・扁平モデル・ベンダーなど）はアプリの設定をそのまま使う。
ケースは `tools/frontistr/run/app-<mill>/` に残るので、`compare.mjs` で表にもできる。
`fistr1` の場所は既定 `~/.local/bin/fistr1`、環境変数 `FISTR1` で変えられる。

| 形式 | 網 | 節点 | 時間 | モデルとの差（既定条件） |
|---|---|---|---|---|
| 2Hi | 細（下の結果 1 と同じ） | 34,099 | 約 10 秒 | 撓み +65 µm（2.2 %）、扁平 ±10 µm |
| 4Hi | 粗（`QUICK`: 接触線で 2 mm → 60 mm、表面層 3 mm、荷重 2 段） | 34,870 | 約 3.5 分 | WR 軸 10 µm（1.7 %）、BUR 軸 14 µm（5.5 %）、WR–BUR 線荷重 0.6 kN/mm（5 %）、出側プロファイル 28 µm |

4Hi・6Hi は接触の非線形解析（拡張 Lagrange、摩擦 0、CG）なので細い網では 26 分（結果 2）かかる。粗い網でも
軸の撓みは 10 µm 台で一致する（節点リングが 36 mm 間隔になるので、荷重が急に変わる板端付近の出側プロファイルは
粗い読みになる）。**6Hi は IR シフトで左右非対称なので全長を解く**（x = 0 の対称面が無いぶん、各ロールの軸の
1 節点を軸方向に止める — 断面ごと止めると回転まで拘束され、軸受が固定端に、チョックのロールが傾けなくなって
BUR の撓みが 22 % 減った）。相手ロールの胴端（6Hi の IR 胴端は WR の胴の内側）にも節点リングを置き、接触が
そこで終わるようにする（無いと 1 セル手前で終わり、線荷重が 15 % ずれる）。幅方向 41 点まで落とすと胴端が
リングの間に落ちて同じことが起きるので、81 点のまま。残るのは浮いている WR・IR の傾き（線荷重の端の集中の
差がモーメントに効く。中央値は数 % 以内）。

ビルドしたアプリ（`npm run preview`）や別オリジンから使うときは `node tools/frontistr/serve.mjs [port]` を立て、
アプリを `?fistr=http://localhost:<port>` 付きで開く。

`npm run check` には `casecheck.mjs`（ケース生成だけ: 3 形式の収束・節点数・板の荷重 = F/4（半分モデル）または
F/2（全長）・接触の群）が入る。`fistr1` は要らない。

## ジョブ: 長い計算の途中の結果を画面へ（`jobs.mjs`・`fieldframe.mjs`）

照合（`/solve`）は 1 回の解の答えを最後にまとめて返す。ロールの応力を画面に実時間で描くために、FrontISTR を**ジョブ**として
走らせ、結果ファイルが 1 つ書き終わるたびに画面へ渡す口を足した（2026-09-19）。

- `POST /__frontistr/jobs { kind, params, load?, substeps?, dryRun? }` → `{ job }`。同時に 1 つ（照合も含めて。動いていれば 409）
- `GET /__frontistr/jobs/<id>`（状態）、`/events`（server-sent events: `state`・`mesh`・`frame { k }`・`progress`）、`/mesh.bin`、`/frames/<k>.bin`、`POST …/cancel`
- `kind: roll-elastic` は 4Hi の WR ＋ BUR（照合と同じ粗い網、接触）に板の荷重を `substeps`（既定 4）段に分けて載せ、段ごとに結果を書かせる。
  節点の von Mises（`NodalMISES`）も出させる
- `dryRun` は網と初期状態（frame 0: 変位 0・応力 0）だけ作って終わる（fistr1 は使わない）。計算前の画面に描く用
- 画面側のつなぎは `src/ui3d/fistrjob.ts`（`FistrJob.start` → イベント → `mesh()`・`frame(k)`・`cancel()`）

**形式（fieldframe）**: 各物体（要素グループ）の外側の面だけを、面に出る節点で番号を振り直して送る（対称面も面なので切り口が見える）。
`mesh.bin` は 1 回、`frames/<k>.bin` は結果ファイルごと（`k` は FrontISTR の結果の番号、0 は初期状態）。先頭に u32 の JSON の長さと JSON
（部品・対称・指標）、4 バイト境界まで 0 埋め、その後に f32 の座標／変位と節点ごとの場（`mises`、接触圧 `cpress` = 接触力 ÷ 節点の面積）、
u32 の三角形。座標はアプリの座標（パスラインが y = 0）にずらしてある。詳しくは `fieldframe.mjs` の先頭。

**書きかけの結果を読まない**: fistr1 は 1 つの結果ファイルを数百 ms かけて書く。次の番号のファイルが出たか fistr1 が終わってから読む
（`finishedResults`）。最新のファイルは、2 回の走査のあいだ大きさが変わらず、ヘッダの節点数ぶんの記録が揃って最後の行が改行で終わって
いれば、次のファイルを待たずに読む（`completeResult`）。待つだけだと各段が次の段の終わりまで出ない — 連成のロールは 1 段が数分なので、
2 段では 1 ラウンドの終わりにまとめて出ていた。読めなかったものは大きさが変わってから、または fistr1 が終わってから読み直す。
実物（4Hi の連成、52,273 節点・11.8 MB）で完全かの判定は 1 回 約 0.3 秒、途中で切った写し 4 通り（最後の数字の途中・最後の改行の前・
半分・最後の行の前）はどれも読まない（2026-09-19、Apple M2）。

実測（2026-09-19、Apple M2・8 GB、OpenMP 4 スレッド、4Hi 既定、4 段）: 表面 6,815 節点・13,622 三角形（`mesh.bin` 246 KB、1 frame 136 KB）、
frame 0 まで 1.3 秒、以後 1 段 約 45 秒、全体 135 秒。von Mises の最大は 2.96 GPa — 板の荷重を駅ごとの節点リングに載せているので、
載せた節点のまわりに局所の集中が出る（荷重の載せ方を細かくすれば下がるはず。照合の撓み・線荷重には効かない）。

`jobscheck.mjs`（`npm run check`）は fistr1 を使わずに確かめる: 小さな網で面の取り出し（共有面が消え、面が外向き＝囲む体積が正）、
形式の読み戻し、書きかけのファイルを読まないこと（fistr1 の代わりの node スクリプトが結果を 3 回に分けて書く: 半分、最後の数字の途中まで、
残り）、最新のファイルを次のファイルが出る前に読むこと（`res.0.1` のあと 1.5 秒止まる）、409、イベントの順、中止。

## 連成: ロールの変形を FrontISTR で解き、定常まで（`couple.mjs`・`rollcase.mjs`・`src/sim3d/coupling.ts`）

照合（上）は「モデルが収束させた荷重を 1 回ソリッドに載せて比べる」だけ。連成はその差を**モデルに戻す**: 同じ荷重の下での
ソリッドの WR 表面（板が出ていく所、BUR の軸受に対する上下変位）とモデルの表面（WR の軸の撓み ＋ WR と板の扁平）の差 δ(x) を、
モデルのギャップの補正にする（`StackSolver.setRollCorrection`）。モデルはその補正のまま板・張力・スクリューを解き直し、荷重が変わるので
ソリッドを解き直し… を、δ と荷重が動かなくなるまで回す（**定常**）。定常では、板は「ソリッドのロールがその荷重で作る表面」で圧延されている。
モデルの接線（剛性）はそのまま使うので、差の分だけを 1 回ごとに取り込む欠陥補正として速く収束する。

```bash
node tools/build-esm.mjs sim3d
node tools/frontistr/couple.mjs tools/frontistr/run/couple '{"stations":81,"stripStations":0,"stripNz":8}'   # 回ごとの表と summary.json
```

- **定常の判定**: 1 回で δ がどの駅でも 0.25 µm 未満しか動かず（ギャップで 0.5 µm、クラウンを読む桁の 1/10）、荷重の変化が 0.1 % 未満
  （モデルの感度 d ln P / d ln μ ≈ 0.15 なので、これより細かく合わせても与えた摩擦係数の不確かさの方が大きい）
- **ロールの網**（`rollcase.mjs`）: 照合の `buildCase` と違い、モデルの駅を使わない（アプリの 301 駅では 17.6 万節点になる）。WR のリングは板の上
  12.5 mm おき、**板端の ±60 mm は 5 mm おき**、板の外は 40 mm おき。BUR は板の上でも 25 mm おき。荷重（駅ごとの q と接触弧）はモデルのスライスから
  リングの位置に補間し、リングごとに自分の受け持ちの幅の分を載せる（荷重の合計はモデルの F/4 に 0.01 % 以内）
- **板端の網**: 板の上を一様に 25 mm おきにすると、板端の手前で δ が −17 → +0.8 → −25 µm と跳び（接触の半幅 5〜8 mm の荷重の立ち上がりを
  25 mm のリングで追えない）、C25 は 54.9 µm になった。板端を 5 mm にすると滑らかになり C25 64.28 µm、2.5 mm では 64.84 µm
  （エッジドロップ 105.69 → 104.90 µm。どちらも 1 回目で比べた）。5 mm で 1 µm 未満に収まるので既定にした
- **橋渡しのジョブ `roll-coupled`**（3D タブ用）: `POST /__frontistr/jobs { kind: 'roll-coupled', params, load: { q, arc, force } }`。橋渡しは
  その `params` でソルバを組むだけ（解かない）で、送られた荷重を載せる。サブステップごとにロールの応力の frame、終わると `result.json` が `{ x, v }`（WR 表面）

**結果（4Hi 既定、関門の格子 81 駅、2026-09-19、Apple M2・8 GB、FrontISTR 5.9、CG・OpenMP 4 スレッド、5.2 万節点）**:

| 回 | δ の最大の動き | 荷重の変化 | 荷重 | C25 | エッジドロップ | 潜在形状 | δ 中央 | 1 回の時間 |
|---|---|---|---|---|---|---|---|---|
| （連成なし） | | | 1477.2 tonf | 68.10 µm | 112.31 µm | 2375 I | | |
| 1 | 21.83 µm | | 1477.4 | 64.28 | 105.69 | 2290 | −20.04 µm | 323 s |
| 2 | 0.48 | 1.1e-4 | 1477.4 | 64.41 | 105.70 | 2295 | −19.74 | 430 s |
| 3 | 0.04 | 2.9e-5 | 1477.4 | 64.41 | 105.70 | 2295 | −19.71 | 414 s（定常） |

3 回・1168 秒で定常。荷重は +0.01 %、C25 は 68.10 → 64.41 µm（−3.7 µm）、エッジドロップ 112.31 → 105.70 µm、潜在形状 2375 → 2295 I-unit。
δ は板中央で −19.7 µm（ソリッドの WR 表面の方が板に近い）から板端の手前 380 mm で −32 µm。
ソリッドの表面には、梁が持たない曲げのポアソン効果（−ν κ R²/2、中央で約 −18 µm）も入っている — 表面の実際の位置として、これもギャップに効く。

**条件を変えて**（同じ網・同じ判定。1 回 5〜13 分、負荷の高い中で）:

| 条件 | 回 | 時間 | 荷重 | C25 連成なし → 連成 | エッジドロップ | 潜在形状 | δ の最大 |
|---|---|---|---|---|---|---|---|
| 既定（板幅 1000 mm） | 3 | 1168 s | +0.01 % | 68.10 → 64.41 µm | 112.31 → 105.70 µm | 2375 → 2295 I | 32.2 µm |
| 板幅 1400 mm | 3 | 1415 s | −0.01 % | 48.17 → 34.03 | 97.69 → 113.62 | 1706 → 2283 | 39.5 |
| WR ベンダー 60 tonf/チョック | 3 | 1834 s | −0.07 % | 56.53 → 43.12 | 97.95 → 80.14 | 1651 → 945 | 20.5 |
| BUR クラウン 300 µm | 3 | 5102 s | 0.00 % | 58.33 → 53.76 | 100.94 → 94.88 | 1768 → 1626 | 30.1 |

どれも 3 回で定常（δ の動きは 2 回目で 0.5〜3 µm、3 回目で 0.04〜0.24 µm）。δ の中央の値は 4 条件とも −19.7〜−20.8 µm。板幅 1400 mm では板端が胴端（WR・BUR とも 1600 mm）の
100 mm 内側に来て、ソリッドの胴端の効き（照合の「結果 2」で見た胴端の線荷重の集中）で δ が板端近く（588 mm）で 39.5 µm になる — 梁のモデルとの差がいちばん大きい条件。
BUR クラウン 300 µm の 1 回は 25〜35 分（ほかの計算と重なり、負荷平均 30 前後の中）。

**積み方の差（2026-09-19 に直した）**: ソリッドはクラウン込みの胴の中央で接するように積む（`cy` に x = 0 の半径、クラウン込み）。モデルは公称の半径で積み、
クラウンを接触の隙間に持つので、荷重の前から、軸受に対して WR がクラウンの重なりの分だけ違う高さにいる。表面はモデルの積み方で読む（`stackOffset` =
WR から圧下ロールまでの x = 0 のクラウン半径の和を引く）。直す前は BUR クラウン 300 µm で δ 全体が 150 µm ずれていた（既定では WR のサーマルクラウンの 10 µm）。
板厚一定では一様なずれはスクリューが吸うので、上の表の荷重・C25・エッジドロップ・形状は変わらない（δ の列は直した後の値）。荷重一定・圧下位置手動では効く。
BUR クラウン 0 → 300 µm でのモデルの WR 表面の変化 −111.6 µm に対し、ソリッドの読みは直すと −112.3 µm（直す前は +37.7 µm）。
ベンダー付きは、照合でもまだ突き合わせていない条件（ベンダー力はソリッドのチョック断面に CLOAD で載せ、モデルは梁の節点に載せる）なので、
差の一部は載せ方の違いかもしれない（未確認）。

制限: ロールのケースは z ≥ 0 の半分（ロール軸の面で対称）で、板の荷重はモデルと同じ Hertz の半楕円を接触の中心に載せる。
実際の接触弧（入側だけ、摩擦丘の圧力）は載せていないので、出口での局所の扁平はモデルの近似（中心の接近量）と同じ扱い。

## 残るもの

- 板の下の軸方向の分割（駅ごとの 1 リング）を細かくし、荷重を駅の間で補間して載せる。4Hi・6Hi の出側プロファイルの照合を板端まで通すにはこれが要る（節点数は 2〜3 倍）
- 6Hi の WR・IR（チョックで浮いている 2 本）の傾きが 0.1 mrad ほど違う。胴端の線荷重の集中（ソリッドは端の 1 リングに集まり、モデルは駅のセルに均す）がモーメントに効いていると見ている。胴端の周辺だけ軸方向を細かく切れば縮まるはず
- ベンダーは CLOAD で載せているが、ベンダー付きの条件では未照合。ハウジング変形モードは対象外（FEM 側は軸受断面を固定）
