# FrontISTR との照合

3D タブのロールスタックモデル（ティモシェンコ梁 ＋ 線接触の扁平）を、同じロールを 3 次元ソリッド要素で解いた
FrontISTR（オープンソースの汎用 FEM）の解と突き合わせる道具。アプリの計算は変えない。

## 何を比べるか

板の荷重 q(x)（スラブ法のスライスが収束させた値）を**両方に同じだけ与える**。ロールモデルが扁平に使う Hertz の
半幅 b(x) の上に半楕円の圧力として掛け、軸受はロールモデルと同じ x = Ls/2 の断面を y に固定する（2 点支持の梁は
静定なので、たわみの形は軸受の剛性に依らない）。違いはロールの力学だけになる:

- **軸のたわみ** v(x) − v(軸受): ネックの段付きと点支持を持つ梁 vs ソリッド
- **扁平**（板の下の局所的な沈み込み）: 線接触の近似式 vs ソリッド表面の押し込み。ソリッドでは曲げのポアソン効果
  （−ν κ R²/2、上下の表面で同じ）が「表面 − 軸」に混ざるので、**下面 − 上面**で読む（2Hi は上面に荷重がない）

## 使い方

FrontISTR は Homebrew の gcc・open-mpi・metis・openblas で自前ビルドする（並列なし・OpenMP あり・MUMPS なしの最小構成で
`~/.local/bin/fistr1`。Xcode のライセンス同意が要る）。

```bash
brew install gcc open-mpi metis openblas cmake
git clone --depth 1 https://github.com/FrontISTR/FrontISTR.git ~/Software/FrontISTR && cd ~/Software/FrontISTR && mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc-16 -DCMAKE_CXX_COMPILER=g++-16 -DCMAKE_Fortran_COMPILER=gfortran-16 \
  -DWITH_MPI=OFF -DWITH_OPENMP=ON -DWITH_METIS=ON -DMETIS_INCLUDE_PATH=/opt/homebrew/opt/metis/include -DMETIS_LIBRARIES=/opt/homebrew/opt/metis/lib/libmetis.dylib \
  -DWITH_MUMPS=OFF -DWITH_ML=OFF -DWITH_LAPACK=ON -DBLAS_LIBRARIES=/opt/homebrew/opt/openblas/lib/libopenblas.dylib -DLAPACK_LIBRARIES=/opt/homebrew/opt/openblas/lib/libopenblas.dylib \
  -DWITH_REFINER=OFF -DWITH_TOOLS=ON -DCMAKE_INSTALL_PREFIX=$HOME/.local
make -j4 && make install
```

```bash
node tools/build-esm.mjs sim3d
node tools/frontistr/case.mjs 2hi                 # 2Hi 既定（関門の格子 81/0/8）を解き、tools/frontistr/run/2hi/ に roll.msh・roll.cnt・hecmw_ctrl.dat・reference.json
tools/frontistr/run.sh tools/frontistr/run/2hi    # fistr1（節点 3.4 万、線形、CG、約 16 s）
node tools/frontistr/compare.mjs tools/frontistr/run/2hi
node tools/frontistr/case.mjs 4hi                 # 4Hi 既定: WR ＋ BUR、接触（拡張 Lagrange、摩擦 0）、荷重 4 分割
tools/frontistr/run.sh tools/frontistr/run/4hi    # 節点 9.2 万、非線形、26 分（Apple M2、OpenMP 4 スレッド、他の計算と重ねて）
node tools/frontistr/compare.mjs tools/frontistr/run/4hi
```

`case.mjs <mill> [outdir] ['{"param":value}']` で条件を変えられる（`Params3D` のキー）。`run/` は git 管理外。各 `run/<mill>/compare.txt` に表の写し。

## アプリ内から（2Hi・4Hi・6Hi）

`npm run dev` の開発サーバーが同じ照合を `/__frontistr` で受ける（`vite.config.ts` が `bridge.mjs` を組み込む）。
3D タブで「解析・表示 ▸ ロールの照合」を **FrontISTR** にすると、計算が収束するたびに今の条件でケースを作って
`fistr1` で解き:

- 「ロール撓み」に各ロールの軸の FEM 曲線、「接触線荷重」にロール同士の線荷重、「扁平量」に板の下の扁平（2Hi）、
  「板厚プロファイル」に出側プロファイル（4Hi・6Hi）を白の破線で重ねる
- 右パネル「FrontISTR 照合」に、板中央の各ロールの撓み・各接触の線荷重のモデル／FEM、最大差（括弧はモデルの最大値に
  対する比）、軸受反力（FEM）と板の荷重、節点数と所要時間
- 上のチップ「FrontISTR」に WR 中央の差と最大相対差

条件を変えると結果は消え、次の収束でまた解く。ミル形式は 2Hi・4Hi・6Hi（12Hi・20Hi のクラスタは未対応: 斜めに
並ぶバッキングベアリングとサドルの接触は別の仕事）。板は関門と同じ「ロールの節点に載せる・弧 8 分割」に固定し、
それ以外の条件（寸法・クラウン・板・荷重・扁平モデル・ベンダー・IR シフトなど）はアプリの設定をそのまま使う。
ケースは `tools/frontistr/run/app-<mill>/` に残るので、`compare.mjs` で表にもできる。
`fistr1` の場所は既定 `~/.local/bin/fistr1`、環境変数 `FISTR1` で変えられる。

| 形式 | 網 | 節点 | 時間 | モデルとの差（既定条件） |
|---|---|---|---|---|
| 2Hi | 細（下の結果 1 と同じ） | 34,099 | 約 10 秒 | 撓み +65 µm（2.2 %）、扁平 ±10 µm |
| 4Hi | 粗（`QUICK`: 接触線で 2 mm → 60 mm、表面層 3 mm、荷重 2 段） | 34,870 | 約 3.5 分 | WR 軸 10 µm（1.7 %）、BUR 軸 14 µm（5.5 %）、WR–BUR 線荷重 0.6 kN/mm（5 %）、出側プロファイル 28 µm |
| 6Hi | 粗（接触線で 3 mm → 80 mm、表面層 4 mm、荷重 2 段、全長） | 50,286 | 5〜8 分 | 板中央で WR 軸 −23 µm（−3 %）、IR 軸 −31 µm（−6 %）、BUR 軸 −4 µm（−2 %）、WR–IR 線荷重 0.6 kN/mm（4 %）、IR–BUR 1.0 kN/mm（6 %）。WR と IR（チョックで浮いている 2 本）の傾きが 0.1 mrad ほど違い、端で 100〜150 µm（最大 11 %）。出側プロファイル（上下 WR の鏡像対称から偶関数部を読む）は板の内側 400 mm で 2 µm 以内、板端の駅で 40 µm（板端＝IR 胴端 500 mm にリング荷重のくぼみが重なる） |

4Hi・6Hi は接触の非線形解析（拡張 Lagrange、摩擦 0、CG）なので細い網では 26 分（結果 2）かかる。粗い網でも
軸の撓みは 10 µm 台で一致する（節点リングが 36 mm 間隔になるので、荷重が急に変わる板端付近の出側プロファイルは
粗い読みになる）。**6Hi は IR シフトで左右非対称なので全長を解く**（x = 0 の対称面が無いぶん、各ロールの軸の
1 節点を軸方向に止める — 断面ごと止めると回転まで拘束され、軸受が固定端に、チョックのロールが傾けなくなって
BUR の撓みが 22 % 減った）。相手ロールの胴端（6Hi の IR 胴端は WR の胴の内側）にも節点リングを置き、接触が
そこで終わるようにする（無いと 1 セル手前で終わり、線荷重が 15 % ずれる）。幅方向 41 点まで落とすと胴端が
リングの間に落ちて同じことが起きるので、81 点のまま。残るのは浮いている WR・IR の傾き（線荷重の端の集中の
差がモーメントに効く。中央値は数 % 以内）。

ビルドしたアプリ（`npm run preview`）や別オリジンから使うときは `node tools/frontistr/serve.mjs [port]` を立て、
アプリを `?fistr=http://localhost:<port>` 付きで開く。

`npm run check` には `casecheck.mjs`（ケース生成だけ: 3 形式の収束・節点数・板の荷重 = F/4（半分モデル）または
F/2（全長）・接触の群）が入る。`fistr1` は要らない。

|---|---|---|---|---|---|---|---|
| 0 | 2.8 | 2982.9 | 3047.5 | +65 (+2.2 %) | 37.3 | 44.9 | +8 |
| 262.5 | 13.5 | 2815.4 | 2880.6 | +65 | 170.5 | 175.0 | +5 |
| 472.5 | 60.9 | 2422.6 | 2492.3 | +70 | 460.7 | 502.1 | +41 |

| 787.5（胴端） | — | 1449.4 | 1526.1 | +77 | — | — | — |

- 軸のたわみ: ソリッドの方が全域で 2〜3 %（65〜77 µm）柔らかい。胴端 → ネックの勾配は両者同じ
- 扁平: 荷重の大きい所（q 13〜67 kN/mm、扁平 170〜500 µm）で ±10 µm 以内。例外は板端の手前 x = 472.5 mm（q が 40 → 61 → 67 kN/mm と急に立ち上がる所）で FEM が 41 µm（9 %）深い — 隣の駅の荷重が効く 3 次元の広がりで、近似式は駅ごとに局所
- 「下面 − 軸」で読むと曲げのポアソン効果が −60〜−75 µm 乗る（中央で −26 µm と負になる）ので、扁平の照合には使わない

- **軸のたわみ**: WR は全域で 3〜8 µm（585 µm に対して 1 % 前後）、BUR は 10 µm 以内（胴端の手前で最大）。梁＋Hertz の接触の組み合わせが、ソリッドどうしの接触解析と同じ形を出している
- **WR–BUR の線荷重**: 胴の中で 0.15 kN/mm（1.5 %）以内。胴端（WR・BUR とも 1.6 m で端がそろう）ではソリッドに端部の集中（16.9 kN/mm）が出て、その手前 60 mm が 4.1 と軽くなる。モデルは駅のセルに均した 5.35 で、合計は同じ

- 解析時間 26 分（接触反復 2〜3 回 × Newton 2〜3 回 × 4 増分、CG）。MUMPS を入れれば短くなる

## 2D タブの板: 弾塑性の圧延解析（strip2d）

`strip2d.mjs` は 2D タブのパス（既定は #1: R 190 mm、2.0 → 1.5 mm、μ 0.06、kf = 1200 (ε+0.010)^0.255 MPa）を、
板厚 × 圧延方向の断面で FrontISTR に解かせる。FrontISTR に剛塑性（流れ定式化）は無いので、**弾塑性・大変形・
摩擦接触の Lagrange 解析**として: 板の上半分（パスラインで対称）を 1 要素厚の 361 ヘキサで切り、全節点を z 拘束して
平面ひずみにする。板は von Mises の弾塑性（kf を σ_f = (√3/2) kf の多直線硬化として等価塑性ひずみに対して）、
ロールは弾性のリングで、内周の節点に振幅表（節点ごと・成分ごと）で回転の強制変位を与える。接触は Coulomb 摩擦 μ・
有限すべり・拡張 Lagrange。

動くまでに踏んだこと（設定は `OPTS` に理由つきで残してある）:

- 板は**最初から噛み込んだ形**（上面がロール面に沿ったくさび、先端は出側板厚で出口の先まで）で始め、ロール面との
  隙間 20 µm を**ロールの締め込み**（第 1 ステップで 40 µm 下げる）で閉じて噛ませる。四角い先端を噛ませても、
  尾端を押し込んでも（細長い板が座屈する）、押さずに回すだけでも（触れない）駄目
- 接触対は **ロール表面の節点 → 板上面の面**。逆だと板の節点がロールの面取り面の間で跳ね回って収束しない
- 増分はロール周で 12 µm（1/16 mrad）。0.5 mm のセルの 1/40。4 倍にすると Newton が切り詰めを繰り返し、やがてセルが
  潰れる（Update_C3D8Fbar: too small average jacob）。`SUBSTEPS` は切り詰めた試行も数えるので上限は公称の 6 倍
- 線形ソルバは組み込みの **DIRECT ＋ CONTACT_ELIM=1**（1 増分 0.2 秒。BiCGSTAB ＋ BILU(2) の 200 倍、SSOR の
  2000 倍。`CONTACT_ELIM` なしの DIRECT は "set positive nrows" で止まる）
- **1 スレッドで走らせる**（`OMP_NUM_THREADS=1`）。`fistr1` 5.9 の接触は OpenMP で競合があり、同じ入力が走るたびに
  違う道をたどる（時に最初の残差が NaN）。1 スレッドなら完全に再現する。加えて `MallocPreScribble=1`（確保した
  メモリを 0xAA で埋める。初期化されない配列の読みが NaN を拾うのを防ぐ）
- `!SECTION, FORM361=FBAR` を制御ファイルに書くと最初の残差が NaN になる（NLSTATIC の既定がもともと F-bar）

```bash
node tools/build-esm.mjs sim2d
node tools/frontistr/strip2d.mjs tools/frontistr/run/strip2d                    # ケース生成（板 0.5 mm × 3 層、ロール表面 1 mm、2760 増分）
OMP_NUM_THREADS=1 tools/frontistr/run.sh tools/frontistr/run/strip2d           # fistr1（1 スレッド、約 10 分）
node tools/frontistr/compare2d.mjs tools/frontistr/run/strip2d                  # FrontISTR vs アプリの材料 FEM vs スラブ法 3 式
```

`compare2d.mjs` は最後の 2 つの結果から、圧延荷重・トルク（幅あたり）、接触弧の圧力 p(x) と摩擦 τ(x)、中立点、先進率、
出側板厚を読み、**FrontISTR が出した出側板厚でアプリを回して**（板厚一定制御）同じパスの材料 FEM とスラブ法（Kármán・
Bland-Ford・Orowan）を並べる。第 2 引数はアプリのパラメータの上書き（`{"mu":0.1}` など）、第 3 引数は `OPTS` の上書き
（網、回転角、増分数）。

**現状（2026-09-16）: 通し計算はまだ再現しない。** 到達した所と、止まっている所:

- 噛み込みは通る: 締め込みで接触が閉じ、摩擦で板が引き込まれ（頭部がロール周速で進み、尾部側に張力）、荷重が
  立ち上がる（20 µm の締め込みで 3 kN/mm、目標は 7.8）。圧延ステップに入って 250 増分ほど進んだ走りもある
- しかし **同じ入力・同じバイナリ・1 スレッドでも、走るたびに結果が変わる**: 最初の Newton 反復で残差が NaN になって
  即終了する走りと、250 増分進む走りが同じディレクトリで交互に出る。`-finit-local-zero` で再ビルドした fistr1
  （`~/.local-init`）と `MallocPreScribble=1` でも変わらない（局所変数・malloc 以外の未初期化か、配列外参照）。
  3D のロール照合（荷重を CLOAD で与える、接触は初期状態から）ではこの不安定さは出ない: 強制変位で接触を閉じる
  この使い方が FrontISTR 5.9 の接触コードの弱い所を踏んでいる
- 進んだ走りも、圧延に入ってから Newton が発散する（残差が 5e-3 → 1e14、増分はロール周 12 µm）。増分をさらに
  細かくしても切り詰めが繰り返され、いずれセルが潰れる
- `INC_TYPE=AUTO` と振幅表の組み合わせは、接触した瞬間に必ず NaN（固定増分なら出ない）

続けるなら FrontISTR の接触コード（`fstr_contact.f90`、`fstr_contact_def.F90`）を Fortran で追う仕事になる。
別の道: CalculiX（面対面の接触が圧延の例題で実績）、あるいは 2D タブ自身の材料 FEM が剛塑性の流れ定式化なので、
そちらは文献値（Orowan の厳密解は既にアプリ内で並べている）との比較に留める。


## 残るもの

- 板の下の軸方向の分割（駅ごとの 1 リング）を細かくし、荷重を駅の間で補間して載せる。4Hi・6Hi の出側プロファイルの照合を板端まで通すにはこれが要る（節点数は 2〜3 倍）
- 6Hi の WR・IR（チョックで浮いている 2 本）の傾きが 0.1 mrad ほど違う。胴端の線荷重の集中（ソリッドは端の 1 リングに集まり、モデルは駅のセルに均す）がモーメントに効いていると見ている。胴端の周辺だけ軸方向を細かく切れば縮まるはず
- ベンダーは CLOAD で載せているが、ベンダー付きの条件では未照合。ハウジング変形モードは対象外（FEM 側は軸受断面を固定）
- 12Hi・20Hi のクラスタ（斜めに並ぶバッキングベアリング、サドル、AS-U）は未着手
